# Spam Detector &mdash; Gmail-style prototype (Naive Bayes, real data only)

A Flask web app that looks like a simplified Gmail inbox and classifies spam
with a **Multinomial Naive Bayes** classifier written from scratch (no
scikit-learn), trained on a real, publicly released, labeled corpus &mdash;
no synthetic or hand-written training examples anywhere.

## What's different from a keyword filter

This does not match a fixed blocklist of words. It learns, from real spam
and real legitimate email, how statistically associated every word in its
vocabulary is with each class, then combines all of an email's words'
probabilities (Bayes' theorem + the "naive" independence assumption) into one
overall spam probability. That's why it can catch spam phrased in new ways,
as long as the words it uses look statistically similar to spam the model
has seen &mdash; see `classifier.py`'s module docstring and the in-app
**About this model** tab for the full math.

## Features

- **Gmail-style folders** &mdash; Inbox, Starred, Sent, and Spam are real,
  separate folders in the left nav, not just a flat list:
  - **Inbox** &mdash; 30 real emails, randomly sampled on every server start
    from a 35-email pool held out of training entirely. Spam is highlighted
    in red, both as a row tag in the list and as inline `<mark>` highlights
    on the strongest spam-indicator words in the email body.
  - **Starred** &mdash; click the star on any inbox email to add/remove it
    here; persists on the server for as long as it keeps running.
  - **Sent** &mdash; Compose &rarr; Send actually goes somewhere: sent
    messages land in this folder. Composing still never runs a live spam
    check (removed on request) &mdash; that only happens in Spam Detector.
  - **Spam** &mdash; the same inbox, filtered to just what the model flagged,
    like a real mail client's spam folder.
  - Search (top bar) and the hamburger menu (collapse the sidebar) both work.
- **Spam Detector tab** &mdash; write or paste any email and check it,
  completely separate from composing. Includes 5 preset real examples, plus
  an "Was this right?" feedback control (see below).
- **Explainability** &mdash; every check shows the actual Naive Bayes math:
  priors, log-probabilities, the sigmoid conversion to a percentage, and a
  table of the specific words that pushed the result toward spam or ham,
  with their counts and likelihood ratios.
- **Feedback / override** &mdash; agree or disagree with a Spam Detector
  verdict. This is a batch-trained model with no online-learning step, so a
  disagreement can't retrain it instantly; the UI says so plainly and tells
  you exactly what retraining it for real would involve, rather than faking
  an instant fix. Session feedback counts show up on the About tab.
- **About this model tab** &mdash; dataset provenance, training set size,
  vocabulary size, and a real held-out accuracy/precision/recall/F1 +
  confusion matrix, computed fresh every time the server starts (not
  training-set accuracy, which is almost always misleadingly high, and not
  a number typed into source code).

## Dataset

**Enron-Spam** (V. Metsis, I. Androutsopoulos, G. Paliouras, "Spam Filtering
with Naive Bayes &mdash; Which Naive Bayes?", CEAS 2006) &mdash; 17,171 real
spam emails and 16,545 real legitimate emails sent to/from actual Enron
employees, 33,716 total real messages. Original source:
http://www2.aueb.gr/users/ion/data/enron-spam/. `prepare_dataset.py`
downloads a pre-built CSV mirror of this exact dataset
(`MWiechmann/enron_spam_data` on GitHub) and builds:

- `data/spam_dataset.csv` &mdash; 33,672 emails, the training set.
- `data/demo_pool.csv` &mdash; 35 emails, held out of training completely.
  These (and only these) populate the inbox and the Spam Detector presets,
  so every email you see in the UI is one the model was never trained on.
  This corpus contains thousands of verbatim duplicate emails (the same
  bulk spam template, the same forwarded thread, sent to many Enron
  addresses), so "held out" is enforced by **text**, not just by row:
  every row anywhere in the corpus that matches a demo email's exact text
  is excluded from training, not just the one row that was sampled.

No row in either file is written, edited, or generated by hand or by an AI
&mdash; both are exact slices of the real downloaded corpus (subject +
message body concatenated, long outliers truncated at 20,000 characters).

## Setup

```bash
pip install -r requirements.txt

# One-time: downloads the real dataset and builds data/spam_dataset.csv +
# data/demo_pool.csv. Needs normal internet access.
python prepare_dataset.py

# Optional: print held-out accuracy/precision/recall/F1 on an 80/20 split.
python evaluate.py

# Run the app
python app.py
```

Then open http://localhost:5000

## Measured accuracy

From `evaluate.py` (80/20 stratified split, seed=42, on `data/spam_dataset.csv`):

| Metric | Value |
|---|---|
| Accuracy | 98.64% |
| Spam precision | 98.74% |
| Spam recall | 98.59% |
| F1 | 98.66% |

Trained on 26,970 emails, tested on 6,702 emails the model never saw during
training. All 35 held-out demo-pool emails (the ones shown in the inbox and
Spam Detector tab) also classify correctly, so what you see in the running
app will always match the labels the real corpus assigns to those emails.

**On train/test leakage from duplicate emails:** this corpus has thousands
of verbatim duplicate messages (the same spam campaign or forwarded thread
sent to many addresses). An earlier version of `evaluate.py` split the data
row-by-row, so a duplicate email could land on both sides of the 80/20
split &mdash; the model could then be tested on the literal text of
something it had already trained on, inflating the reported accuracy
without proving the model could generalize. `stratified_split()` now groups
identical email text together first, so every copy of a duplicate goes to
the same side. The honest, leak-free accuracy above is close to the
original (flawed) 98.65%, so the earlier number wasn't wildly wrong, but it
wasn't a clean measurement either. The same text-based exclusion is used to
build the demo pool itself (see Dataset, above), so the 35 emails you
actually see in the app are genuinely unseen by the model, not just
excluded by row index.

## Project layout

```
app.py                 Flask routes
classifier.py          BayesianSpamClassifier (Naive Bayes from scratch)
dataset.py             Loads training data; builds inbox sample + presets
textclean.py           Cosmetic detokenizer so real emails read naturally
prepare_dataset.py     One-time real-data download + train/demo split
evaluate.py            Honest held-out accuracy check + reusable metrics
data/
  spam_dataset.csv     Training set (generated by prepare_dataset.py)
  demo_pool.csv         Held-out demo set (generated by prepare_dataset.py)
templates/index.html   Single-page app shell
static/css/style.css   Gmail-style styling
static/js/app.js       Frontend logic (fetches the API above, renders it)
```

## Notes

- `data/*.csv` are generated files (not checked in as source) &mdash; run
  `prepare_dataset.py` once after cloning/copying this project.
- The classifier is retrained from `data/spam_dataset.csv` every time
  `app.py` starts (a few seconds); nothing is pickled/cached between runs.
- Sender names/addresses shown in the inbox are synthesized for display
  only (the raw corpus has no sender field) and are never seen by the
  classifier &mdash; only each email's real subject/body text is classified.
